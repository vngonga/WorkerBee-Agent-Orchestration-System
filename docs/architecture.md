# WorkerBee Architecture

This document describes the architecture of the WorkerBee
multi-agent orchestration system.

## Architecture Overview

WorkerBee is a layered, parallel multi-agent orchestration system.

A human operator, called the **Keeper**, submits a work request.
**HIVEMIND** interprets the request, identifies constraints, and creates
a Directed Acyclic Graph (DAG) of tasks.

The tasks are assigned to specialized AI agents called **Bees**.
Tasks within the same layer can execute in parallel, while the layers
execute sequentially.

After a layer is completed, **CORA**, the Coordinator Bee, synthesizes
the results and prepares handoff instructions for the next layer.

Quality review, self-critique, revision, escalation, and human decision
points are integrated into the workflow.

## Core Architecture Components

| Component | Description |
|---|---|
| **Keeper** | Human operator who submits requests, answers clarifications, reviews gates, and provides direction |
| **HIVEMIND** | Strategic meta-agent that interprets requests, plans tasks, and synthesizes final deliverables |
| **Bee** | Specialized AI worker assigned a particular role and task |
| **Layer** | Group of tasks that can execute in parallel |
| **Task** | Individual unit of work assigned to a Bee |
| **Artifact** | Output generated by a task, such as research, analysis, content, or code |
| **Gate** | Decision point requiring human input |
| **CORA** | Coordinator Bee responsible for layer synthesis and handoffs |
| **Call Sign** | Unique identifier assigned to each Bee instance |

## Layered Execution Model

WorkerBee organizes work into layers.

Tasks within a layer can execute in parallel. Layers execute
sequentially so that later agents can build on artifacts produced
by earlier agents.

A typical workflow may follow this pattern:

1. **Intake & Planning** - HIVEMIND interprets the request and develops the plan.
2. **Research & Analysis** - Specialized Bees gather information and structure the problem.
3. **Content Development** - Content Bees create the required deliverables.
4. **Quality Review** - Quality Bees evaluate artifacts and identify required revisions.
5. **Synthesis & Delivery** - HIVEMIND combines approved artifacts into the final deliverable.

   ## DAG-Based Task Planning

WorkerBee uses a Directed Acyclic Graph (DAG) to organize work.

HIVEMIND decomposes a complex request into smaller tasks and organizes
those tasks into layers.

Tasks within the same layer may execute concurrently, while dependencies
between layers determine the execution order.

This allows WorkerBee to combine parallel processing with structured
dependencies between tasks.

## Specialized Agent Architecture

WorkerBee separates responsibilities across specialized agents.

| Agent | Family | Responsibility |
|---|---|---|
| **HIVEMIND** | HIVEMIND | Strategic planning and final synthesis |
| **Coordinator** | CORA | Layer coordination and handoffs |
| **Research** | RYE | Research, sources, and citations |
| **Analysis** | AXEL | Analysis, structure, frameworks, and matrices |
| **Content** | CLOVER | Content and deliverable creation |
| **Quality** | QUINN | Quality review, auditing, and scoring |
| **Innovation** | NOVA | Creative alternatives and variants |

## Execution Lifecycle

The WorkerBee execution lifecycle consists of several major phases.

### 1. Intake

The Keeper submits a project request.

### 2. HIVEMIND Read

HIVEMIND analyzes the request to identify:

- The project goal
- Constraints
- Open questions
- Risks
- Out-of-scope items
- Estimated cost and execution time

### 3. Clarification

When necessary, HIVEMIND generates clarification questions for the Keeper.

The Keeper's answers become additional constraints for the project.

### 4. Planning

HIVEMIND creates the DAG of layers and tasks and assigns work to
specialized Bee roles.

### 5. Dispatch

The plan is materialized into layers and tasks, and each Bee receives
a unique call sign.

### 6. Execution

WorkerBee executes tasks layer by layer.

Tasks within the active layer can run in parallel.

### 7. Review and Revision

Agents evaluate their own work through self-critique.

Quality Bees perform additional structured reviews and may request
revisions when material issues are identified.

### 8. Layer Coordination

After a layer is completed, CORA synthesizes the outputs and provides
handoff instructions to the next layer.

### 9. Human Decision Gates

When a decision requires human judgment, WorkerBee creates a Gate for
the Keeper.

### 10. Synthesis and Delivery

After all layers are completed, HIVEMIND synthesizes the artifacts and
WorkerBee compiles the final deliverable.

## Quality and Revision Architecture

WorkerBee incorporates multiple quality-control mechanisms.

### Self-Critique

After creating an artifact, non-Quality Bees evaluate their own work.

A Bee can determine that its artifact should:

- Ship
- Be revised
- Be escalated

### Quality Review

Quality Bees perform structured reviews of upstream artifacts.

The review can evaluate dimensions such as:

- Goal alignment
- Citation integrity
- Specificity
- Internal consistency
- Accessibility
- Actionability

If significant problems are identified, the system can dispatch the
artifact for revision.

### Revision Control

Revision cycles are limited to prevent endless loops.

When the revision limit is reached and the issue remains unresolved,
the system escalates the decision to the Keeper.

## Human-in-the-Loop Control

The Keeper remains involved throughout the WorkerBee workflow.

The Keeper can:

- Answer clarification questions
- Review decision gates
- Provide new constraints
- Redirect work during execution
- Pause or resume tasks
- Skip tasks
- Cancel tasks
- Review escalations
- Request changes after delivery

This architecture combines AI automation with human oversight for
important decisions.

## Mid-Flight Steering

The Keeper can provide natural-language instructions while a project
is running.

The Coordinator interprets the instruction and can translate it into
actions such as:

- Requeue a task
- Skip a task
- Raise a decision gate
- Record an informational note
- Add a new project constraint

New constraints can be incorporated into future task prompts, allowing
the workflow to adapt while execution is still in progress.

## Agent-to-Agent Communication

WorkerBee supports communication between Bee agents.

During the thinking phase, an agent can request information from another
agent using peer messaging.

Messages can be routed by:

- Exact Bee call sign
- Agent role or family
- General broadcast

Responses can then be incorporated into the requesting agent's work.

## Artifact and Revision Tracking

Task outputs are stored as artifacts.

Artifacts maintain lineage information that records changes and revisions
over time.

This provides traceability between:

- Tasks
- Agents
- Generated artifacts
- Revisions
- Quality reviews
- Final deliverables

The system also maintains an event stream that records significant actions
throughout a project run.
